# Exchange Online Review – script-generated Markdown report

Create a generic, customer-parameterised PowerShell script in the `Exchange Online\Exchange Online review` folder. It reads Exchange Online, EOP and Defender for Office 365 configuration without changing anything, and can optionally read Purview data. It writes a data-only Markdown review report and optional CSVs, and ships with a README covering usage and permissions.

## Decisions (from user)
- Deliverable: **a report generated by the script** (no separate manual template).
- Scope: the user's list **plus** Mailbox hygiene, Org & security config, Mail flow & hybrid, Compliance & retention.
- Style: **data only**. The report documents current configuration, with no RAG ratings or recommendations.
- Generic: the customer is set with a parameter (`-CustomerName`). Nothing tenant-specific is hard-coded.
- **Purview is opt-in** (`-IncludePurview`). The user may not have Purview permissions. By default the script connects to Exchange Online only and never calls `Connect-IPPSSession`.

## Files to create (folder `C:\Github\Collaboration\Exchange Online\Exchange Online review\`)
- `Invoke-ExchangeOnlineReview.ps1`: collects the data and generates the Markdown.
- `README.md`: purpose, prerequisites, permissions (split into Exchange-only and Purview), parameters, examples, section list, cmdlets per section, troubleshooting. Follows the repo's README style, e.g. `Exchange Hybrid\README-EdgeBlocking-Assessment.md`.
- `.gitignore`: ignores `Reports/`.

## Script design
**Parameters**
- `-CustomerName` (mandatory), `-ReviewedBy`, `-ReviewDate` (default today), `-OutputPath` (default `.\Reports`).
- Auth: interactive by default. Optional `-UserPrincipalName`. App-only via `-AppId -CertificateThumbprint -Organization`, used for both EXO and IPPS.
- `-IncludePurview`: connects to Security & Compliance PowerShell (`Connect-IPPSSession`) and adds the Purview sections (see "Purview option" below). Off by default.
- `-IncludeMailboxStatistics`: per-mailbox sizes, last logon, and inbox rules that forward externally. Slow on big tenants.
- `-IncludeMessageTrace`: 7-day inbound/outbound summary via `Get-MessageTraceV2`.
- `-IncludeGraph`: optional Microsoft Graph data: Secure Score plus Exchange-related controls, and holders of the Entra "Exchange Administrator" role.
- `-ExportCsv` (full detail tables as CSV next to the report), `-MaxRows` (default 50; longer Markdown tables are truncated with a "see CSV" note), `-DnsServer` (optional, for `Resolve-DnsName`).

**Structure / conventions** (follow `Exchange Online\Get-TransportRules.ps1`):
- Comment-based help and `[CmdletBinding()]`.
- Module check for `ExchangeOnlineManagement` (latest v3).
- `Connect-ExchangeOnline -ShowBanner:$false`, and `Connect-IPPSSession` only when `-IncludePurview` is set. Disconnect in `finally`.
- Coloured `Write-Host` progress.
- Helpers:
  - `ConvertTo-MdTable`: escapes `|` and newlines, joins arrays with `; `, truncates at MaxRows.
  - StringBuilder-based section writer.
  - `Invoke-Section` wrapper: runs each section in its own try/catch. On an error, a missing cmdlet or missing permission, it writes *"Not available: <reason>"*, logs the reason to the Collection Log appendix, and continues.
- Output file: `<OutputPath>\EXO-Review_<CustomerName-sanitised>_<yyyyMMdd>.md`, UTF-8.
- Strictly read-only: only Get-* cmdlets and `Resolve-DnsName`.

## Purview option (`-IncludePurview`)
- **Off (default):** no IPPS connection. Each Purview section still appears in the TOC with the text *"Skipped – Purview data not collected (run with -IncludePurview)"*, so the report shows clearly what wasn't reviewed.
- **On:** the script connects to IPPS.
  - If the connection fails (no permission, or MFA/licence issue), it prints a warning, marks every Purview section *"Not available: could not connect to Security & Compliance PowerShell – <reason>"*, and continues with the EXO sections. The script doesn't abort.
  - If an individual cmdlet fails with an access-denied error, only that subsection is marked *"Not available: insufficient permissions"*.
- **Cmdlets that need IPPS (only run when on):**
  - Alert policies: `Get-ProtectionAlert`
  - Purview retention covering Exchange: `Get-RetentionCompliancePolicy` / `Get-RetentionComplianceRule`
  - DLP covering Exchange: `Get-DlpCompliancePolicy` / `Get-DlpComplianceRule`
  - Sensitivity labels and label policies: `Get-Label`, `Get-LabelPolicy`
  - Optional: `Get-ComplianceTag` (retention labels)
- **Stay in the EXO session (always collected):** EXO MRM retention policies/tags, IRM/OME config (`Get-IRMConfiguration`, `Get-OMEConfiguration`), journal rules, Unified Audit Log status (`Get-AdminAuditLogConfig`), and all EOP/Defender policies (anti-phish/spam/malware, Safe Links/Attachments, TABL, quarantine, advanced delivery, preset policies). These run in the Exchange Online session, not IPPS.
- The report header records "Purview data collected: Yes / No / Failed (reason)".
- README lists the roles needed for Purview: Compliance Administrator, Security Reader + Compliance Data Administrator, or View-Only Organization Management plus the Purview "View-Only DLP Compliance Management" / "View-Only Retention Management" / "Sensitivity Label Reader" roles. It also lists Global Reader as the minimum for the EXO-only run.

## Report sections (Markdown)
0. **Header**
   - Customer, tenant display name, tenant ID/initial domain, review date, reviewed by, collected by (UPN), module version, script version.
   - Data sources collected (EXO / Purview / Graph / Mailbox stats / Message trace: Yes/No).
   - Table of contents and a summary counts table.
1. **Organization config**
   - `Get-OrganizationConfig`: modern auth (OAuth2ClientProfileEnabled), AuditDisabled, CustomerLockBoxEnabled, MailTips, EwsEnabled, FocusedInbox.
   - `Get-ExternalInOutlook` (external sender tagging).
   - `Get-TransportConfig`: SmtpClientAuthenticationDisabled, AllowLegacyTLSClients, max send/receive size, ExternalPostmasterAddress, journaling NDR address.
   - `Get-AdminAuditLogConfig`: Unified Audit Log ingestion.
2. **Recipients**: counts by RecipientTypeDetails:
   - User, shared, room, equipment, scheduling and discovery mailboxes.
   - Mail users, guest mail users, mail contacts, public-folder mailboxes.
   - Inactive mailboxes (`-InactiveMailboxOnly`) and soft-deleted mailboxes.
3. **Mailbox hygiene**
   - Litigation hold, archive enabled/auto-expanding, retention hold.
   - Mailbox audit enabled/disabled, audit bypass (`Get-MailboxAuditBypassAssociation`).
   - Forwarding (ForwardingSmtpAddress, ForwardingAddress, DeliverToMailboxAndForward).
   - Shared/room mailboxes with sign-in enabled (`Get-User` AccountDisabled).
   - How mailboxes are spread across role assignment policies.
   - With `-IncludeMailboxStatistics`: top N by size/quota, not logged on for more than 90 days, inbox rules that forward or redirect externally.
4. **Groups**
   - Static distribution groups, mail-enabled security groups, dynamic distribution groups (with recipient filter).
   - Microsoft 365 groups: Teams-enabled, private/public, external senders allowed, hidden from GAL, guest count.
   - Room lists.
   - Groups with no owners/ManagedBy, and groups that accept external senders.
5. **Domains & email authentication**
   - Accepted domains: DomainType (Authoritative/InternalRelay/ExternalRelay), Default, Initial.
   - DNS per domain:
     - MX (does it point to EXO?)
     - SPF record
     - DKIM (`Get-DkimSigningConfig`: enabled, selector CNAMEs, key size, last rotation)
     - DMARC record parsed into p, sp, pct, rua, ruf, adkim/aspf
     - MTA-STS (`_mta-sts`), TLS-RPT (`_smtp._tls`), BIMI (`default._bimi`)
   - DKIM/DMARC for the MOERA (onmicrosoft.com) domain.
   - ARC trusted sealers (`Get-ArcConfig`).
6. **Mail flow**
   - Inbound and outbound connectors: type, enabled, TLS, certificate domain, restricted IPs, smart hosts, CloudServicesMailEnabled.
   - **Enhanced Filtering for Connectors** per inbound connector: On/Off (derived from the settings), EFSkipLastIP, EFSkipIPs, EFUsers, EFTestMode.
   - Transport rules: name, state, priority, mode, sender address location, comments, WhenChanged, plus enabled/disabled counts.
   - Remote domains: AutoForwardEnabled, AllowedOOFType, TNEF, CharacterSet.
   - Journal rules.
   - **HVE accounts** (`Get-MailUser -HVEAccount`), with an explicit "No HVE accounts in use" line when there are none.
   - Optional message trace summary.
7. **Hybrid & migration**: `Get-OnPremisesOrganization`, `Get-IntraOrganizationConnector`, `Get-MigrationEndpoint`, `Get-MigrationBatch` (status).
8. **Sharing**
   - Organization relationships (`Get-OrganizationRelationship`): domains, free/busy level, enabled.
   - Individual sharing policies (`Get-SharingPolicy`): default, domains/actions, enabled.
   - Availability address spaces.
9. **Client access**
   - OWA mailbox policies: key settings and which one is default.
   - Mobile device access rules (`Get-ActiveSyncDeviceAccessRule`) and the org default access level (`Get-ActiveSyncOrganizationSettings`).
   - Mobile device mailbox policies.
   - Protocol usage counts (`Get-EXOCASMailbox`): POP, IMAP, EWS, ActiveSync, MAPI, SMTP AUTH.
   - Authentication policies and legacy application access policies.
10. **Permissions / RBAC**
    - Role groups and members (`Get-RoleGroup` + `Get-RoleGroupMember`).
    - User roles, i.e. role assignment policies, with their assigned roles and mailbox counts.
    - Custom management roles, direct user role assignments (outside role groups), management scopes.
    - **RBAC for Applications**: `Get-ServicePrincipal` (DisplayName, AppId, ObjectId) joined to `Get-ManagementRoleAssignment -RoleAssigneeType ServicePrincipal` (role, custom resource scope / admin unit).
    - Optional Graph data: holders of the Entra Exchange Administrator role.
11. **Threat protection (EOP / Defender for O365)**: always collected (EXO session). Each policy is joined with its rule (state, priority, included/excluded users, groups and domains).
    - Anti-phishing: impersonation, mailbox intelligence, spoof intelligence, thresholds, honor DMARC policy, quarantine policy per action.
    - Anti-spam:
      - Inbound: action per verdict, BCL, allowed/blocked senders and domains.
      - Connection filter: IP allow/block lists, safe list.
      - Outbound spam: limits, AutoForwardingMode.
    - Anti-malware: common attachment filter, number of file types, ZAP, notifications.
    - Safe Attachments: action, redirect. Plus `Get-AtpPolicyForO365` (SPO/OneDrive/Teams, Safe Documents).
    - Safe Links: email/Teams/Office, click-through, URL rewrite, do-not-rewrite list.
    - Preset security policies (`Get-EOPProtectionPolicyRule`, `Get-ATPProtectionPolicyRule`) and built-in protection (`Get-ATPBuiltInProtectionRule`).
    - Tenant Allow/Block List: Sender, Url, FileHash and IP via `Get-TenantAllowBlockListItems`; spoof entries via `Get-TenantAllowBlockListSpoofItems`; with expiry dates.
    - Advanced delivery:
      - SecOps mailboxes: `Get-SecOpsOverridePolicy` / `Get-ExoSecOpsOverrideRule`.
      - Phishing simulations: `Get-PhishSimOverridePolicy` / `Get-ExoPhishSimOverrideRule` (domains, sending IPs), and simulation URLs via TABL `-ListSubType AdvancedDelivery`.
    - Quarantine policies (`Get-QuarantinePolicy`: end-user permissions, notifications) and the global quarantine notification settings.
    - Priority account protection (`Get-EmailTenantSettings`), user-reported message settings (`Get-ReportSubmissionPolicy` / `Get-ReportSubmissionRule`), Teams protection (`Get-TeamsProtectionPolicy`).
    - If Defender cmdlets are missing, the section says "Defender for Office 365 not licensed / cmdlet not available".
12. **Alert policies** *(Purview, `-IncludePurview`)*: `Get-ProtectionAlert`: name, category, severity, enabled, system/custom, notify users.
13. **Compliance & retention**
    - Always collected (EXO): MRM retention policies/tags, IRM/OME config, Unified Audit Log status.
    - *Purview (`-IncludePurview`)*: retention policies covering Exchange, DLP policies covering Exchange (with mode), sensitivity labels and label policies, retention labels.
    - Optional Graph data: Secure Score plus Exchange-related improvement actions.
14. **Appendix**: collection log (sections skipped or failed, with reason), parameters used, run duration, cmdlet reference.

## Risks / considerations
- **Permissions:** Global Reader covers most EXO/EOP Get-cmdlets. Purview is opt-in so that missing Compliance permissions never block the EXO review.
- **Performance:** `-IncludeMailboxStatistics` and `-IncludeMessageTrace` are opt-in because they scale per mailbox or are throttled.
- **Licensing:** the Defender for O365 P1/P2 sections degrade gracefully when those licences aren't present.
- **DNS:** `Resolve-DnsName` is Windows-only, which is fine on Windows 11. PowerShell 7 is recommended.
- **Sensitive data:** the report contains tenant configuration and user names. `Reports/` is git-ignored.
